## 6. 过程中确认的关键事实 / 踩过的坑

1. **`T.verf` 不是硬件 erf**：实测是 7 阶泰勒 `(2/√π)(x−x³/3+x⁵/10−x⁷/42)`，|x|=1 误差 4.5e-3、|x|=3 误差 39。Erf 改用 A&S 7.1.26，离线 2 M 点最大绝对误差 5.8e-7。
2. **uint8 的 `out_idx=[1]` 会把输出分配成 float32**：计算本身没错，是 dtype 分配错误。规避：`out_idx=[]` + 调用方 `empty_like`，或转 int8 视图。
3. **原生 `dtype="bool"` 编译通过但执行挂死**：bool 一律用 int8 bit-view；且 `vnot` 对 bool 不成立（`~0 = 0xFF` 仍为真），必须 `fill(ones,1)` + `vxor`。
4. **2D `T.Kernel` 第二维会被静默串行化**（Day 4 结论，本轮沿用）：一律 1D 扁平 grid。
5. **`vbrc` 标量绑定必须写在 `@T.prim_func` 体内**，写在工厂作用域会报 `input vector and output vector must have same rank`。
6. **wrapper 集成必须按两段式调用面适配**：`factory(N, dtype_str, block_size=bs)(bs)(x)`；单段或保留尾部 `, N` 会在 build 期失败。
7. **`integrate_kernel.py` 的 wrapper 改写不幂等**：scaffold 预埋的 selection 注释块会残留，出现重复块头/重复 perf_opt 注释（Elu/Erf/BitwiseNot 都出现过）。功能无害，需人工清理；已写进各算子 RETROSPECTIVE。
8. **集成 smoke 只验证 import，不验证调用面**：Expm1 的旧 wrapper 调用 `(x, N)` 能通过 smoke，问题要等到全量 report 才暴露。
